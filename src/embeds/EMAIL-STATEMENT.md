## Sending confirmation experiment

SVG/WAAPI implementation, no Lottie runtime or JSON dependency. `src/lib/effects/sending-confirmation.js` supplies the transient overlay. The established Icon - Check Circle definition/instance stays intact underneath and becomes the final static state. Overlay uses the exact original check subpath and ring subpath, each separately addressable with pathLength=1. Additional dots are native SVG circles. No IDs, raster artwork, or CDN dependency.

At the check reveal (two normal durations from viewport trigger), three dots fade in sequence without scaling; the title reads Email sending. After two normal durations of opacity cycles, each dot heads to the right and follows a circular orbit with the global stagger between starts. Angular travel deliberately accelerates (quadratic angle), as requested; the straight approach uses primary easing and sampled orbital travel uses linear segment interpolation. A continuous ring draws behind the orbit, dots fade away with linear opacity, then the check draws using primary easing and the computed Global Styles fast duration. The original text is restored to Email sent only after the completed check draw. Total visible sequence ends at 5482ms with the currently verified tokens, including the existing reveal entrance delays. Duration/stagger/ease/opacity ratio come from live Global Styles; fast duration is resolved via computed animation-duration to support its calc expression.

CSS sits in Global Styles → Animation Components. `es-send-animation` owns absolute overlay geometry; the existing instance root is temporarily hidden only while data-es-sending is present. Setup failure, disposal, hidden tab, reduced motion, and full offscreen exit dispose every WAAPI track, remove the overlay, clear the timer, and restore the original editable text/icon. Offscreen exit rearms the full entrance as before. Reduced motion and disabled custom code show the original static Email sent artwork.

Actual desktop Preview capture verified opacity loading, ring strokeDashoffset progressing to zero, check strokeDashoffset progressing to zero, then overlay removal and original text. ## Loop and entrance revision (current behavior)

Supersedes the one-shot experiment timing above. Exactly three circles at x=12,20,28 (8-unit equal spacing). Initially ring/check path opacity is zero as well as strokeDashoffset=1: zero-length dashes with round caps otherwise create extra visible dot artifacts. Dots join at staggered times, then orbit with fixed 120-degree phase separation and a shared accelerating angular clock.

Entry waits two global staggers after the 70% viewport threshold: label begins at 400ms, card at 1170ms with current tokens. The label moves 40 design pixels horizontally; card rises 48 design pixels. Both outer targets fade for a full normal duration (770ms), while internal items keep the shorter linear opacity fade and 200ms sequence. Check/inner contents start only after both outer entrances; first sending loop delay is 1940ms. The delay gives the viewer a short settling interval after reaching the section. All parts remain visible in Designer/static fallback; only successful motion setup arms the viewport enhancement.

Sending/check loop is about 7.9 seconds after its initial reveal delay. Ring and check draw, title crossfades to Email sent, confirmation holds for two normal durations, check undraws, ring retracts/fades, three equally spaced orbital dots reappear and travel back to their loading row, title crossfades to Email sending. The overlay remains mounted across cycles; prior tracks/timers are cleared at each cycle, so allocations remain bounded. Outer label/card/attachments do not repeat while in view. Full viewport exit disposes the loop and rearms the entrance. Hidden-tab/reduced-motion/disposal restore the original icon/text. Returning from a hidden tab can begin a new entrance. Exact original SVG icon definition remains unchanged.
